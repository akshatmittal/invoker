# Upstream anti-slop comparison

Checked 2026-09-01 against upstream `main` at [`e8c4880471b23ab7f216fba7b27d173a6ef07d4c`](https://github.com/dmmulroy/anti-slop/commit/e8c4880471b23ab7f216fba7b27d173a6ef07d4c), tagged `v0.1.2`. Upstream identifies itself as private `oxlint-plugin-anti-slop@0.1.2`; it is intended to be vendored and explicitly has no official npm package ([package metadata](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/package.json#L2-L29), [distribution policy](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/README.md#L7-L9)).

## Result

Yes, there are material updates. The local `packages/anti-slop` package has all 15 upstream generic rule names, but only six rule implementations still match upstream byte-for-byte. Nine rules and their shared type-analysis code are behind upstream's August 31 correctness work. Upstream also has one new, separate, opt-in Effect rule.

The local production source is an almost exact snapshot of upstream commit [`e8100a1`](https://github.com/dmmulroy/anti-slop/commit/e8100a10da49858cfa8d26883d170e9cc8281988), before upstream tags `v0.1.0`, `v0.1.1`, and `v0.1.2`. The only local source difference at that baseline is a typecheck-only fallback in `shared/dictionary-types.ts`: `unsafeMembers[0] ?? null` instead of `unsafeMembers[0]`.

The shared implementation behind several of these changes is a new cached lexical type-alias environment. It understands block scope, forward references, competing bindings, built-in shadowing, type parameters, generic substitution/defaults, and cycles ([resolver](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/src/shared/type-alias-resolution.ts#L1-L250)). Upstream documents the deliberate boundary: same-file syntax and lexical scope are analyzed, but imported definitions and cross-file call signatures are not ([analysis boundaries](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/README.md#L117-L119)).

## New optional rule

Upstream added a separate `anti-slop-effect` plugin containing `no-service-constructor-imports`. It rejects named `make<CapabilityName>` imports from relative project modules in runtime code, but permits tests/specs, package/path-alias imports, default imports, and static constructors ([entry point](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/src/effect/index.ts#L1-L13), [rule implementation](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/src/effect/rules/no-service-constructor-imports.ts#L1-L52)).

Invoker does not currently contain an Effect dependency or Effect imports, so this is not useful here yet. If copied into the workspace package later, it needs an explicit package subpath export; upstream's package metadata exports only `./src/index.ts`, while its documented vendored setup references the Effect source file directly ([Effect configuration](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/README.md#L74-L91)).

## Config, docs, and architecture differences

- Upstream exports no recommended preset/config object; its generic default export is still only `meta` plus `rules` ([entry point](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/src/index.ts#L19-L41)). No preset is missing locally.
- Upstream requires `oxlint` and `@oxlint/plugins` to stay on the same exact version ([manual installation guidance](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/README.md#L25-L27)). Local package metadata uses peer range `^1.78.0` and root `oxlint` also uses a caret range, so a future install can drift them apart.
- Upstream's README now explains every rule's precise boundary, both configurable options, violation examples, Effect setup, and known analysis limits ([rule reference](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/README.md#L93-L119)). The local package README only lists rule IDs and a minimal setup example.
- Upstream has an adjacent RuleTester file for each of its 16 rules and runs lint, all rule checks, typecheck, and vendored-asset drift verification in `pnpm check` ([scripts](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/package.json#L11-L17)). Local has no rule checks; importing them would conflict with this repository's explicit “never create tests” instruction unless that policy is changed.
- Upstream maintains a bundled installation skill whose copied production sources are checked byte-for-byte against canonical `src` ([sync script](https://github.com/dmmulroy/anti-slop/blob/e8c4880471b23ab7f216fba7b27d173a6ef07d4c/scripts/sync-skill-assets.mjs#L5-L40)). That machinery is for vendoring into arbitrary repositories and is unnecessary for this workspace package.
